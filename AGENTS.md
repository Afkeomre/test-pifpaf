# AGENTS.md — PifPaf Bloggers Dashboard

Проект для агентов и разработчиков: тестовое задание заказчика и его структура.

## Расшифровка ТЗ (исходный текст заказчика)

> Сделать сайт для внутренних блоггеров, где будет обновляться по ссылке из инсты просмотры, дата, обложка и все органично подтягиваться. Данные подтягиваются из apify по api (бесплатки хватит). Там же будет список, как бд красивая или в форме ленты этих видео. Дизайн возьми с фигмы, в светлых тонах, как для пинтерест девчонок в стиле нашего приложения — pifpafai.com. На сайте как для наших блоггеров личные кабинеты типо будет все считаться, то есть разные аккаунты с разными рилсами — они туда грузят и все удобно видно. Красивый формат дашборда. Аналитики и личного кабинета. JavaScript, SQL

### Что значит по пунктам
| Требование заказчика | Реализация |
|---|---|
| «Данные подтягиваются из apify по api» | модуль `server/apify.js`: по ссылке на рилс и по нику профиля, `run-sync-get-dataset-items` |
| «Обновляться просмотры, дата, обложка, органично» | кнопка «Обновить статистику» + кэш снапшотов в БД (экономия бесплатного тарифа) |
| «Список как красивая бд или лента видео» | главная — равномерная сетка рилсов всех блоггеров (grid, без masonry-градиентов) |
| «Личные кабинеты: разные аккаунты с разными рилсами» | регистрация/вход (bcrypt + JWT), каждый видит только свои рилсы |
| «Красивый формат дашборда, аналитика» | `/dashboard.html`: стат-карточки, график просмотров по дням, история роста по каждому рилсу |
| «Дизайн с фигмы, светлые тона, пинтерест девчачий, стиль pifpafai.com» | палитра Beauty/Spa (pink #EC4899 + lavender #8B5CF6), фон #FDFBFF, шрифты Manrope/Inter |

## Стек
- Node.js 22, Express 4, better-sqlite3 (SQL — файл `data/pifpaf.db`)
- Frontend: vanilla JS + HTML/CSS (без сборщика), графики — собственный canvas-модуль
- Auth: bcryptjs + JWT в httpOnly-cookie

## Структура
```
server/
  index.js            # Express: статика + роуты + error-handler
  db.js               # подключение SQLite, выполнение schema.sql
  schema.sql          # users, reels, reel_snapshots
  apify.js            # интеграция Apify + мок-генераторы
  seed.js             # демо-данные (мок-блоггеры)
  scripts/smoke-apify.js  # разовая проверка связи с Apify
  routes/
    auth.js           # register/login/logout/me + middleware ME
    reels.js          # CRUD рилсов, add/sync-profile/refresh
    analytics.js      # overview, me, reel/:id
public/
  index.html          # лента (feed) + js/feed.js
  login.html / register.html + js/auth.js
  dashboard.html      # ЛК блоггера + js/dashboard.js
  css/style.css       # дизайн-система
  js/api.js           # утилиты (fetch-обёртка, форматирование, тосты)
  js/chart.js         # canvas-графики (bar/line), без библиотек
```

## Режимы работы
- `APIFY_MOCK=1` (по умолчанию) — синтетические данные, Apify не вызывается. Подходит для демо/разработки, без лишних расходов.
- `APIFY_MOCK=0` — живой вызов `api.apify.com`. Для этого нужен валидный `APIFY_TOKEN`.

Токен находится в `.env` (НЕ в репозитории — `.gitignore`).

## Команды
```bash
npm install          # установка зависимостей
npm start            # запуск → http://localhost:3000
npm run seed         # засеять демо-данные (перезатирает всех @demo.ru)
npm run smoke        # смоук-тест Apify (APIFY_MOCK=0 для реального вызова)
```

## Демо-доступ
- `alina@demo.ru` / `demo1234` — и любые `*@demo.ru` из seed.
- Демо-рилсы помечены бейджем «демо» (`is_mock=1`).

## Правила для агентов
- Не коммитить `.env` и `data/*.db`.
- После правок схемы: удалить `data/pifpaf.db` и перезапустить `npm run seed`.
- Проверка: `node --check` для JS-файлов, `npm run seed`, разовый вызов API.
- Лента/дашборд должны работать и в мок-режиме (основной сценарий демо).
