# Деплой на Koyeb — пошаговая инструкция

Сайт задеплоен на [koyeb.com](https://www.koyeb.com) (бесплатный тариф). Два раздела:
инструкция для себя (сделать один раз) и готовый текст для заказчика.

---

## Часть 1. Как задеплоить (делается один раз)

### Что нужно заранее
- Аккаунт GitHub с этим репозиторием.
- Токен Apify (лежит локально в `.env`, строка `APIFY_TOKEN=...`).

### Шаги

1. **Регистрация**: зайди на [app.koyeb.com](https://app.koyeb.com) → **Sign up with GitHub** (карта, как правило, не нужна).
2. **Новое приложение**: на вкладке Overview нажми **Create Web Service**.
3. **Подключи репозиторий**: выбери **GitHub**, установи Koyeb GitHub App и дай ему доступ к репозиторию `test-pifpaf`, затем выбери этот репозиторий и ветку `main`.
4. **Сборка**: оставь билдер **Buildpack** — он сам найдёт `package.json`, выполнит `npm install` и запустит `npm start`. Вручную команды указывать не нужно (при желании Run command можно прописать явно: `npm start`). Версия Node берётся из `engines` в `package.json` (у нас ≥22).
5. **Инстанс и регион**: Instance type — **free** (0.1 vCPU / 512 MB RAM / 2 GB SSD), регион — Frankfurt или Washington, D.C. (для free другие недоступны).
6. **Порт**: в разделе Exposed ports оставь порт по умолчанию **8000** (protocol http, path `/`). Чтобы приложение слушало именно его, добавь переменную окружения `PORT=8000` (см. шаг 7) — код уже читает её (`process.env.PORT`).
7. **Переменные окружения** (раздел Environment): добавь четыре строки —

   | Key | Value |
   |---|---|
   | `PORT` | `8000` |
   | `APIFY_TOKEN` | твой токен из `.env` |
   | `APIFY_MOCK` | `0` |
   | `SESSION_SECRET` | любая длинная случайная строка |

   Случайную строку можно получить командой:
   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```
8. **(Необязательно, но полезно)** Health checks: в настройках сервиса смени проверку порта с TCP на **HTTP** и укажи путь `/api/health` — тогда Koyeb будет считать сервис живым, только когда Express реально отвечает.
9. Нажми **Deploy** и подожди статуса **Healthy** (первая сборка ~3–5 минут).
10. Открой адрес вида `https://<имя-сервиса>-<организация>.koyeb.app` — должна открыться лента с демо-данными (они сеются автоматически при пустой базе).

> Важно: именно переменная окружения `APIFY_MOCK=0` включает живой режим.
> Без неё (или без токена) сайт работает на мок-данных — это безопасный дефолт.

## Часть 2. Инструкция для заказчика (можно переслать как есть)

> Сайт доступен по ссылке: **https://<твой-адрес>.koyeb.app**
>
> **Как посмотреть демо без регистрации:** на главной уже есть лента рилсов трёх демо-блоггеров. Можно войти за любого из них: `alina@demo.ru` / пароль `demo1234`.
>
> **Как протестировать на живом рилсе:**
> 1. Нажмите «Войти» → «Регистрация», заполните имя, e-mail, пароль и укажите свой Instagram-ник.
> 2. В кабинете нажмите **«Добавить рилс»** и вставьте ссылку на рилс, например:
>    `https://www.instagram.com/reel/Cxxxxxxx/`
>    Через несколько секунд появятся обложка, просмотры, лайки, комментарии и дата.
> 3. Кнопка **«Подтянуть профиль»** добавляет сразу последние рилсы по Instagram-нику.
> 4. Кнопка **«Обновить статистику»** освежает цифры по всем рилсам пользователя (сделана отдельно, чтобы экономить лимиты Apify).
>
> **Один нюанс:** сайт работает на бесплатном тарифе и «засыпает» после часа без посетителей. Если страница не отвечает — просто обновите её ещё раз, сервис просыпается за несколько секунд.

## Часть 3. Правила бесплатного тарифа Koyeb

| Параметр | Значение | Что это значит для нас |
|---|---|---|
| Цена | $0, карта обычно не нужна | деплой ничего не стоит (карту могут попросить только если платформа не сможет автоматически проверить, что ты человек) |
| Инстансы | 1 бесплатный web-сервис на аккаунт | хватает на наш единственный сайт |
| Ресурсы | 0.1 vCPU / 512 MB RAM / 2 GB SSD | для демо достаточно |
| Регион | Frankfurt или Washington, D.C. | выбираем ближайший к аудитории |
| Сон | засыпает после 1 ч без трафика, отключить нельзя | просыпается за несколько секунд |
| Диск | эфемерный, подключить volume на free нельзя | база обнуляется при каждом сне/редеплое |
| Домен | свой домен можно, HTTPS бесплатно | pifpafai-домен подключим позже без доплат |

**Главное следствие — эфемерный диск.** SQLite-файл (`data/pifpaf.db`) живёт только пока сервис не уснул или передеплоился. Поэтому:

- при старте сервер **автоматически сеет демо-данные**, если база пустая (см. `server/index.js`) — лента никогда не выглядит сломанной;
- **зарегистрированный заказчиком аккаунт и его рилсы пропадут**, когда сервис уснёт или после нового деплоя. Для короткой демонстрации это нормально;
- загруженные аватарки (`public/uploads/`) живут на том же эфемерном диске и тоже обнуляются — пользователи без аватарки увидят кружок с инициалами, это не ломает ничего;
- если нужно, чтобы данные жили весь день демонстрации: повесь бесплатный «пингер» ([cron-job.org](https://cron-job.org)) на адрес сайта раз в ~30 минут — сервис не уснёт;
- для постоянного хранения данных нужен платный план (Starter, pay-as-you-go: eco-инстансы от ~$2/мес, без сна) либо перенос базы на внешний PostgreSQL.

**Apify (про токен):** бесплатный план даёт ограниченный кредит вычислений в месяц (~$5). Один вызов скрейпера стоит доли цента, так что тестов заказчика хватит с запасом. Расход виден в консоли Apify.
